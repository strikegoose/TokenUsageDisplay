# 2026-08-07 弹窗自适应高度构建审核纪要

## 背景

- 用户反馈菜单栏弹窗只显示 Kimi 和智谱，DeepSeek/ARK/阿里云余额看不到。
- 定位：不是数据问题（5 个服务配置齐全、缓存余额正常），而是弹窗旧固定高度把后三张卡片截在折叠线下。
- 修复代码（`0616cb6` 弹窗自适应高度）早已提交，但正在运行的 App 是修复前一分钟打的旧包 —— 重新构建 + 重启即恢复。

## 审核结论（Claude Code + GLM 5.2 审核，后端 open.bigmodel.cn）

**通过，可以发布。** 核心设计正确：估算偏小时最坏只是需要滚动，不会再藏卡片。

遗留偏差（均不阻断）：

1. **[中] errorMessage 行未计入高度估算**（`MenuBarContentView.swift:282-298` 的 `cardHeight`）——刷新失败时卡片变高但估算不变，是唯一"正常运行中频繁发生且影响可见性"的偏差，建议作为后续小补丁：`cardHeight` 透传 `errorMessage`，失败时 +36pt 左右。
2. [低] `isBalance` 判定与 `ServiceCardView.swift:14-16` 不一致，DeepSeek 有用量时高估约 14pt。
3. [低] 单卡时 `max(natural, 300)` 下限偏高，留白约 80pt。
4. [低] `screenMax` 取 `NSScreen.main`，多显示器时未必是状态栏所在屏。
5. [信息] header 常量 52 未含 ccProviderMenu 行（少算约 13pt，与 bottom 多算基本抵消）。
6. [信息] `observeViewModel` 只观察 count/percentage/status，`resetTime` 单独变化不触发重排（ScrollView 兜底）。
